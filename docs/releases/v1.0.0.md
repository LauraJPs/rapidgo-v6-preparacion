## RapidGo V6 – Preparación de pedidos · v1.0.0

Pipeline Big Data de punta a punta para detectar **demoras y acumulación de pedidos en comercios**
antes de que el pedido llegue al repartidor. Equipo 3 · Línea de Profundización I – Big Data.

### Qué incluye
- **Producer** con 30 comercios simulados (normales, lentos y saturados) → Kafka
  `rapidgo.preparacion.eventos` (3 particiones, key `comercio_id`, ADR-001).
- **Spark Structured Streaming**: limpieza, deduplicación, tiempo real de preparación, demoras,
  ventanas de 5 min con watermark, KPIs K1–K3 y alertas A1/A2 (A2 confirmada en 2 ventanas, ADR-002).
- **Data Lake** Parquet `raw → processed → curated` con checkpoints.
- **Airflow**: DAG `rapidgo_v6_preparacion` de 6 tareas con retries, XCom, calidad, KPIs diarios,
  consolidación de alertas, frescura de los datos y reporte (ADR-003).
- **Quality gate** en GitHub Actions: sintaxis, pruebas, validación del DAG con DagBag y prueba de
  punta a punta con Docker Compose. Este release lo publicó `release.yml` solo después de que el
  CI quedó en verde.

### Novedades de la Semana 4
- Todo arranca con `docker compose up -d --build`: `kafka-init` limpia el Data Lake cuando Kafka es

- `scripts/verificar_pipeline.sh`: verificación local de contenedores → Data Lake → DAG → reporte (#14).
- Job `pipeline-e2e` y workflow `release.yml` (quality gate antes de publicar) (#15).
